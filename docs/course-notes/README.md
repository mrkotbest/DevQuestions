# Разборы курса «Архитектура .NET веб приложений»

Конспект-наставник к курсу [sachkov-learn.net/courses/web-architecture](https://sachkov-learn.net/courses/web-architecture).
На каждое практическое видео — отдельный файл: что изменилось в коде, почему автор сделал
именно так, чем этот вариант хорош, где он упрощён ради урока, и какие есть альтернативы.

Это **не пересказ видео**. Видео даёт «как», разбор — «почему» и «а как ещё бывает».

## Эталон автора

Репозиторий курса: [KirillSachkov/DevQuestions](https://github.com/KirillSachkov/DevQuestions).
Ветки этапов называются одинаково с нашими: `features/issue-1`, `issue-3`, `issue-5`, `issue-6`,
дальше `issue-9`, `issue-11`, `issue-13`, `decorators`, `github-actions`.

**Ветка не равна видео.** Автор коммитит один раз в конце ветки, поэтому одна ветка может
покрывать два урока: в `features/issue-6` единственный коммит называется «добавил
инфраструктурные слои и обработку ошибок» — это видео 2.4 и 2.5 вместе. Разделить их
по истории git нельзя, только по содержимому файлов.

Исходники у автора лежат в `DevQuestions/src/`, имена проектов местами отличаются
(`DevQuestion.Infrastructure.Postgres`, пространство имён `FulltextSeatch` — с опечаткой).
Посмотреть файл эталона, не клонируя репозиторий:

```bash
gh api "repos/KirillSachkov/DevQuestions/contents/DevQuestions/src/<путь>?ref=features/issue-5" --jq .content | base64 -d
```

## Как устроен каждый разбор

1. **Что появилось** — файлы и структура, кратко
2. **Теория** — понятие, вокруг которого построен шаг: агрегаты, слой приложения,
   порты и адаптеры. Разбирается целиком, а не упоминается
3. **Разбор по шагам** — почему автор принял именно такое решение и какую задачу оно решает
4. **Как развивать дальше** — что добавляется к этому коду на следующих шагах
5. **Что можно было бы сделать иначе** — альтернативные подходы и их цена
6. **Сверка с эталоном** — чем твой код отличается от авторского и почему
7. **Проверь себя** — вопросы, на которые стоит уметь ответить после видео

Заглушки, `NotImplementedException` и незаконченная проводка — нормальное состояние учебного
проекта в середине курса, поэтому они не разбираются как недостатки. Где это важно для
следующих шагов, указан порядок доделки.
